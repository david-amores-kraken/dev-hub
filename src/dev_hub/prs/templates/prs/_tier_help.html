What each review level does
LevelThe automatic choice whenWho reviewsSpend cap
note Every change is mechanical: renames, whitespace, lockfiles. Nobody. The brief just says so. ${{ budgets.note }}
light Up to {{ thresholds.light.max_substantive_lines }} substantive lines in {{ thresholds.light.max_files }} files or fewer, and nothing risky. One general reviewer, so a short brief. ${{ budgets.light }}
standard Everything between light and large. Six specialised reviewers: domain, correctness, cross-client, tests, conventions and naming. A UX reviewer joins when the diff changes something a user sees. ${{ budgets.standard }}
large {{ thresholds.large.min_substantive_lines }} substantive lines or more, or {{ thresholds.large.min_files }} files or more. The same reviewers as standard, each told to read the whole diff in order and to say what they couldn't cover. ${{ budgets.large }}

The suggested level in the list comes from the PR's size alone: all changed lines and files, a migration or settings file spotted by its path, and PRs that only touch lockfiles. The automatic choice counts only substantive lines (moves and whitespace excluded) once the PR is fetched, so it can differ. Anything risky (a migration, raw SQL, a transaction, permissions, settings) rules out light there. Picking a level yourself overrides all of this. The cap stops a run that costs more than expected, and the brief is built from whatever the reviewers finished.
